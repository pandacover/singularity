# Procedural memory in shipped coding-agent products and open-source tools (as of Oct 2026)

## Claude Code: CLAUDE.md, auto memory, rules, Skills, and the Claude API memory tool

### Takeaway
Claude Code layers memory written by humans (CLAUDE.md/AGENTS.md, path-scoped `.claude/rules/`) with memory Claude writes itself (auto memory: a `MEMORY.md` index of at most 200 lines/25KB loaded every session, plus topic files read on demand) and with Skills, which load progressively. Auto memory deliberately skips anything that can be derived from code or git history. That is the same lesson Singularity reached on its own.

### Cited Findings
- Two mechanisms carry knowledge across sessions. CLAUDE.md is written by the user ("Instructions and rules", loaded every session). Auto memory is written by Claude ("Learnings and patterns", per repository, shared across worktrees, "first 200 lines or 25KB" loaded every session). Both are "context, not enforced configuration". To block an action, the docs point to a PreToolUse hook. — [Claude Code docs: memory](https://code.claude.com/docs/en/memory.md)
- Auto memory saves four note types, recorded in a frontmatter `type` field: `user`, `feedback` (corrections and approaches the user confirmed), `project` ("ongoing work, deadlines, and decisions that Claude can't derive from the code or git history") and `reference`. "Claude skips anything it can derive from the codebase, such as architecture, file paths, or debugging fixes." It also skips whatever CLAUDE.md already says. — [Claude Code docs: memory](https://code.claude.com/docs/en/memory.md)
- Storage is `~/.claude/projects/<project>/memory/`, keyed by git repo, machine-local, and kept out of the transcript retention sweep. `MEMORY.md` is an index, "one line per memory". Topic files such as `feedback_testing.md` are not loaded at startup; "Claude reads them on demand using its standard file tools". — [Claude Code docs: memory](https://code.claude.com/docs/en/memory.md)
- Freshness mechanics: after a write, Claude Code measures `MEMORY.md` against the limits. Near a limit, it reminds Claude to "merge or drop stale entries". Over a limit, it returns an error telling Claude to rewrite the index. Since v2.1.214 a `modified` ISO-8601 timestamp is written into frontmatter, so Claude can judge "how current the fact is". There is no automatic expiry: files "stay until you or Claude edits or deletes them". — [Claude Code docs: memory](https://code.claude.com/docs/en/memory.md)
- Auto memory is on by default in local sessions. It can be switched off with `autoMemoryEnabled: false` or `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. Subagents can have their own memory directory through a `memory` field. — [Claude Code docs: memory](https://code.claude.com/docs/en/memory.md)
- CLAUDE.md guidance: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence". Path-scoped rules (`.claude/rules/*.md` with `paths:` globs) load only when matching files are touched. Subdirectory CLAUDE.md files load lazily, when Claude reads or edits a file in that directory. `@path` imports do not reduce context cost. AGENTS.md is read natively from v2.1.277. — [Claude Code docs: memory](https://code.claude.com/docs/en/memory.md)
- Skills (Oct 16, 2025; released as an open standard Dec 18, 2025) are directories with a `SKILL.md`. Its YAML frontmatter `name`/`description` is preloaded into the system prompt. The body is read when relevant, and bundled files or scripts are read only when needed, so a skill "can contain effectively unbounded context". Bundled scripts can run without their code entering context. — [Anthropic Engineering: Equipping agents with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- The Skills post suggests asking Claude to capture "successful approaches and common mistakes" into a skill. It states that self-authored skills (agents that "create, edit, and evaluate" skills on their own) are a future goal. It gives no quantitative results. — [Anthropic Engineering: Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- Context engineering (Sep 29, 2025): Claude Code is a hybrid. CLAUDE.md goes in up front, and glob/grep retrieve "just in time", which avoids "stale indexing". Structured note-taking (for example NOTES.md) and compaction are the other techniques. Compaction carries forward "the five most recently accessed files". The post introduces "context rot": recall degrades as the token count grows. — [Anthropic Engineering: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- The Claude API memory tool (Sep 29, 2025) is a file-based memory directory that Claude can create, read, update and delete through tool calls. It runs client-side, and the developer controls storage. On an internal agentic-search eval, memory tool plus context editing gave +39% over baseline, and context editing alone gave +29%. Context editing cut tokens by 84% in a 100-turn web-search eval. These are not coding evals. — [Claude: Managing context on the Claude Developer Platform](https://claude.com/resources/articles/context-management)

### Inferences
- Anthropic's design choices match Singularity's eval findings closely. Auto memory explicitly excludes what code or git can provide (Singularity found git history "gives the same info for free"). It stores `feedback` corrections, which are the closest analogue of trap/mistake warnings. It keeps an always-loaded index small and loads detail lazily, which is the same shape as Skills and as claude-mem's layered retrieval.
- Claude Code has no verification step against the code before a memory is used. Its staleness defence is a timestamp plus model judgment. Copilot's citation check (next section) is the stronger design.

### Gaps
- No Anthropic-published numbers on whether auto memory or Skills reduce tokens or raise success in coding tasks. The release date of auto memory was not confirmed from a primary source; the docs cite only version gates such as v2.1.214.

## Other shipped products: GitHub Copilot, OpenAI Codex, Cursor, Windsurf, Devin, Cline, Jules, Kiro, Factory, Augment

### Takeaway
GitHub Copilot Memory is the most rigorous design. Agents store facts with `file:line` citations, check the citations against the current branch before use, and let unused facts expire after 28 days. It is also the only one with published A/B results (PR merge rate 83%→90%). Codex added an automatic two-phase extraction and consolidation pipeline that also writes learned `skills/`. Cursor removed auto-memories in 2.1 in favour of Rules, and Devin is deprecating Knowledge in favour of Skills. The industry is converging on version-controlled, conditionally loaded instruction files and skills, with auto-memory as an optional local layer.

### Cited Findings
**GitHub Copilot Memory**
- Each memory is a subject, a fact, citations (`file:line` references) and a reason. Agents write one through a `store_memory` tool call when something looks actionable later. GitHub rejected an offline curation service (dedupe, conflicts, expiry) as too costly at its scale. — [GitHub Blog, "Building an agentic memory system for GitHub Copilot" (Jan 15, 2026)](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/)
- Recall: at session start, "the most recent memories for the target repository" are put in the prompt. A search tool and weighted prioritization are planned. — [GitHub Blog](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/)
- Verification: before applying a memory, the agent checks the cited code. If the code contradicts the memory, it stores a corrected version. If the memory checks out, it re-stores it to refresh the timestamp. The check added no significant latency. In a stress test with adversarial memories (contradicting the code, fake citations), agents caught and corrected them "in all cases". — [GitHub Blog](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/)
- Results: in an A/B test, the Copilot coding agent's PR merge rate rose from 83% to 90% (+7 points). Copilot code review got +3% precision and +4% recall offline; in A/B, positive feedback on comments rose from 75% to 77%. Both A/B results had p < 0.00001. Memories were generated from historical tasks, with abandoned branches overrepresented as noise. — [GitHub Blog](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/)
- Docs (public preview): used by the cloud agent, code review, CLI and agentic autofix. "Any stored fact or preference that goes unused is deleted after 28 days", and successful validation or use resets the timer. Facts from PRs closed without merging are validated before use. Memory is scoped to the repository; user preferences cite user quotes. Repo owners can review and delete facts. — [GitHub Docs: Copilot Memory](https://docs.github.com/en/copilot/concepts/agents/copilot-memory)

**OpenAI Codex**
- Built-in memory preview: 16–17 Apr 2026, according to a secondary source. Phase 1 extracts a raw memory and a summary per idle, completed session and redacts secrets. Phase 2 is a serialised consolidation sub-agent (no network, local writes only) that ranks inputs by usage count, then recency. Files live in `~/.codex/memories/`: `MEMORY.md`, `memory_summary.md`, `raw_memories.md`, `rollout_summaries/`, and `skills/` for learned procedural memories. Flags are `generate_memories`/`use_memories`, and unused memories are dropped after `max_unused_days`. — [Daniel Vaughan, Codex memory deep dive (Apr 18, 2026)](https://codex.danielvaughan.com/2026/04/18/codex-built-in-memory-system-deep-dive/) (secondary; it cites [developers.openai.com/codex/memories](https://developers.openai.com/codex/memories) and [codex-rs memories README](https://github.com/openai/codex/blob/main/codex-rs/core/src/memories/README.md), which I did not verify directly)

**Cursor**
- Cursor removed Memories intentionally in 2.1.x (user report Nov 25, 2025). Staff told users to "Export memories" to an `.mdc` file and paste it into User or Project Rules. — [Cursor forum: Are my memories gone?](https://forum.cursor.com/t/are-my-memories-gone/144057)
- Custom Modes were removed in 2.1 at the same time (staff, Nov 23, 2025). — [Cursor forum](https://forum.cursor.com/t/custom-modes-and-memories-gone-in-2-1/143744/2)

**Windsurf / Cascade (now under Devin docs)**
- Cascade auto-creates memories when it sees useful context, or on request ("create a memory of..."). They are stored in `~/.codeium/windsurf/memories/`, are not committed, are scoped to the workspace, are retrieved when Cascade judges them relevant, and cost no credits. They apply only to the legacy Cascade agent. — [Devin docs: Cascade memories](https://docs.devin.ai/desktop/cascade/memories)
- Rules have activation modes: `always_on`, `model_decision` (only the description is in the prompt, the body is read when relevant, which is progressive disclosure), `glob`, and `manual` (`@rule`). Limits are 6,000 characters for global rules and 12,000 per workspace file. The docs recommend Rules or AGENTS.md over auto memories because they are version-controlled and shareable. No staleness mechanism is documented. — [Devin docs: Cascade memories](https://docs.devin.ai/desktop/cascade/memories)

**Devin**
- Knowledge items each carry a trigger description, and Devin retrieves an item when its work matches the trigger, rather than loading everything. Knowledge can be pinned to no repo, one repo, or all repos. Devin auto-suggests Knowledge from feedback in chat and can suggest updates to existing items. Knowledge is now deprecated and migrating to "Skills in Plugins". — [Devin docs: Knowledge](https://docs.devin.ai/product-guides/knowledge.md)

**Cline**
- Memory Bank is a "documentation methodology" implemented through custom instructions, not a built-in feature. It consists of `projectbrief.md`, `productContext.md`, `activeContext.md`, `systemPatterns.md`, `techContext.md` and `progress.md`. Cline "MUST read ALL memory bank files at the start of EVERY task", and "update memory bank" triggers a full review. Freshness depends on manual or prompted updates. — [Cline docs: Memory Bank](https://docs.cline.bot/features/memory-bank.md)

**Google Jules**
- Reported as upcoming in Sep 2025: repo-specific memory that could be generated from feedback, including PR reviews. This is unconfirmed. — [TestingCatalog (Sep 27, 2025)](https://www.testingcatalog.com/googles-jules-update-will-get-memory-and-file-selector.md)

### Inferences
- Copilot's citation check is a direct answer to Singularity's "stale memories misled agents" finding. Singularity already keeps places as blocks found in the code at use time. Adopting a "validate, then refresh the timestamp or rewrite" loop, plus expiry of unused items, would follow the only design with A/B evidence.
- Several products moved away from opaque auto-memories toward inspectable, version-controlled artifacts: Cursor (to Rules), Devin (Knowledge to Skills) and Windsurf (whose docs recommend Rules). Codex instead invests in automatic consolidation, including procedural `skills/`, which is closest to Singularity's mining of runs.
- Trigger-based retrieval is common: Devin's trigger descriptions, Windsurf's `model_decision` and globs, Claude rules' `paths`. All of them are closer to Singularity's cue matching than to embedding search.

### Gaps
- Not researched within the tool-call budget: Kiro steering-file modes, Copilot custom instructions (`.github/copilot-instructions.md`, `*.instructions.md` with `applyTo`), Aider `CONVENTIONS.md`, Amazon Q rules, Sourcegraph, and Factory Droid. Factory's memory doc now redirects to an AGENTS.md page ([docs.factory.ai](https://docs.factory.ai/guides/power-user/memory-management)), but I did not fetch it. Augment's agent doc page did not mention Memories ([Augment docs](https://docs.augmentcode.com/using-augment/agent)).
- Whether Jules shipped memory is not confirmed.
- No published numbers for Codex memory, Windsurf memories, Devin Knowledge or Cursor memories. Why Cursor removed memories was not explained publicly in the threads I read.

## Open-source memory layers and skill-learning tools; published evidence

### Takeaway
Open-source layers such as claude-mem capture everything through hooks and recall it in layers. The strongest public evidence that learned procedural memory helps coding agents comes from Letta's skill learning (Terminal-Bench 2.0: +36.8% relative, 15.7% lower cost). Independent academic studies show that context files cost more than 20% extra inference and help little unless they state non-standard practices. LLM-generated ones can even hurt.

### Cited Findings
- claude-mem uses 5 lifecycle hooks (SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd) to capture tool-use observations and semantic summaries. It stores them in SQLite (FTS5) plus Chroma vectors behind a local worker. Context is injected at session start, and MCP tools `search` → `timeline` → `get_observations` give progressive disclosure: about 50–100 tokens per index hit versus 500–1,000 for full detail, with a claimed "~10x token savings". The listing shows about 29.4k GitHub stars. These are unverified listing figures. — [mdskills.ai: claude-mem](https://www.mdskills.ai/plugins/claude-mem)
- Letta skill learning (Dec 2, 2025): trajectories and verifier logs from Letta Code on Terminal-Bench 2.0 (89 tasks) go through reflection, then skill-creator, which writes `.md` skills covering "approaches, common pitfalls, and verification strategies". From trajectory only: +21.1% relative (+9 points), 15.7% lower cost, 10.4% fewer tool calls. With verifier feedback as well: +36.8% relative (+15.7 points). Caveat: skills were learned on the same tasks used for evaluation, with one model and no variance reported. — [Letta: Skill learning](https://www.letta.com/blog/skill-learning)
- Gloaguen et al., "Evaluating AGENTS.md" (arXiv 2602.11988, v3 Sep 29, 2026): context files "do not generally improve task success rates" and raise inference cost by more than 20%. This holds for LLM-generated and developer-written files alike. Agents follow instructions well, but repository overviews do not help. Files are useful "for specifying non-standard coding practices". — [arXiv 2602.11988](https://arxiv.org/abs/2602.11988)
- Per a secondary summary: in Gloaguen et al., developer-written files gave about +4% success and LLM-generated ones about −3%. Lulla et al. (arXiv 2601.20404; 10 repos, 124 PRs, Codex) found human AGENTS.md cut median runtime 28.6% and median output tokens 16.6%. dos Santos et al. (arXiv 2606.15828) found 91% of 100 repos' files carry at least one "smell" (Context Bloat 42%). — [Daniel Vaughan summary (Jul 27, 2026)](https://codex.danielvaughan.com/2026/07/27/do-auto-generated-agents-md-files-actually-help-codex-cli/) (secondary; preprints)
- GitHub Copilot Memory A/B: merge rate 83%→90% (see the previous section). This is the only product-scale controlled result found. — [GitHub Blog](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/)
- Anthropic memory tool plus context editing: +39% on an internal agentic-search eval, not coding. — [Claude context management](https://claude.com/resources/articles/context-management)

### Inferences
- The evidence fits Singularity's results. Generic overviews and information the agent can rediscover (code structure, git history) add cost without gains. Content that carries non-obvious or non-standard practices, pitfalls and verification steps is what helps: Letta's skills explicitly encode pitfalls, and Gloaguen et al. find value only in non-standard practices. This supports Singularity leaning on trap/mistake warnings.
- Letta's gains came from verifier feedback (+6.7 points over trajectory only). Singularity's "learns from results" graph is analogous. Commit and test outcomes play the role of the verifier.
- Every result is vulnerable to train/test overlap (Letta) or to the product being measured by its own vendor (GitHub). The academic studies are the most independent, and they are the most negative.

### Gaps
- Not researched within budget: Mem0, Zep/Graphiti, Basic Memory, Serena's `.serena/memories` (search hits only, no primary source fetched), and other "self-improving" Claude Code skill tools. No independent benchmark of claude-mem's token savings was found.
- No published coding-agent eval was found that isolates warnings/pitfalls from other memory content.
