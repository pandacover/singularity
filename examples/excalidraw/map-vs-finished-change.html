A map, or the finished change?

memory_x gives the agent a map of what worked last time. Our applied draft would give it the finished change and ask it to check it. This page shows what our runs say about each, on the three toggle tasks (minimap, rulers, presenter).

Update, 2026-10-04: the applied draft is dropped. Memory is there to help the agent do the task, not to write the change for it. The turn and dollar charts below still show where runs spend their effort.

What to take from memory_x

One check command

memory_x keeps the check command whole. Our draft listed four finishing steps, and the end of each run took four turns. Free, no model, and it helps plain v1 too.

No model call unless it pays

Drafting costs more than half a whole exact-script run. It can pay on big changes like the toggles, not on small ones like the shortcut tasks (11-13¢ a whole run).

Being wrong costs it less

A wrong map costs a few reads; a wrong applied change stays. So test the applied draft on tasks unlike the ones memory learned from, not only on toggles.

Dropped: the applied draft, the draft as text and the patch variant. Memory helps the agent; it doesn't write the change.

Proposed instead: one check command that past runs proved, in place of v1's separate finishing steps, then a list from the logs of what v1's runs still look up before their first edit.
