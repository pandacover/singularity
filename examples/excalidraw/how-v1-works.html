Memory v1, from empty to learning

What the local-first memory does at each step, shown on real data. It learns from six runs of two tasks, then a new task arrives (a “Presenter mode” setting) and gets the workflows it needs, with no model call at task start. Click a step, or use the ← → keys.

Everything below is from the excalidraw runs: memory version 2 (sealed as memory-local-first), the six runs it learned from, and one Presenter-mode run that used it. In the measurement each run had its own copy of memory, and the eval passed v1's hooks to it; here they share one memory home, the way it would work in your own sessions once the hooks are installed there.

Sources: memory runs/excalidraw/memory/v1-cues (version 2) and the records in it; the Presenter run runs/excalidraw/v1cues-toggles/runs/toggle-presenter-r1-62362b (its hand-over log and transcript); the code in src/workflows/. The picks in step 7 run a line-for-line copy of Cues.ts, checked against it on all nine suite tasks; the place lookups in step 8 were computed with v1's own Places.ts and Locate.ts; the learning round in step 11 is the one tried in C:\singularity-workspaces\_v1-evolve-test.
